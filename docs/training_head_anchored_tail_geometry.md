# Training head-anchored tail geometry v4

This opt-in recipe refreshes only named rows in existing 19-landmark training
reviews whose saved status contains `tail_derivation_failed:snout_extension_too_long`.
It does not change the production subject-shape writer, the legacy centerline
default, the 19 landmark schema, or the canonical body heading. Historical
review runs remain intact. Each upgrade publishes a new selector-ineligible
crop/mask/seed/editable-review set through the existing refresh publisher.

`head_anchored_skeleton_path_v1` skeletonizes the connected body mask and
enumerates its endpoints. A head endpoint must win a score based on distance
to the eye midpoint plus 0.25 times distance to the mask-derived snout by
at least 6 px. The selected caudal endpoint must have a graph distance at
least 5 px beyond the next candidate. A mask-supported snout bridge joins
within the first 24 px of the head branch; candidate joins score lateral
offset plus 0.20 times head-branch arclength. The existing 48 px straight
bridge limit, 3.0 length ratio and 24 px extra-length indirect-path checks,
spline fit, and all 11 in-mask tail
station checks still apply. Ambiguous endpoints or unsupported bridges keep
their failure reasons; validity is never forced. The recipe records these
effective bounds and weights, method name, and `id` ending in `_v4`. The new
6/5/24 px bounds and score weights are versioned heuristics tested on frozen
training fixtures, not population-calibrated thresholds.

The explicit publisher is
`fisheye.training.mask_tail_apply_refresh.upgrade_training_tail_geometry_version`.
It accepts a current mask/pose review pair, expected mask edit revision,
durable upgrade ID, and explicit target row indices. It validates the saved
long-snout failure status, source identity, row identity, mask and pose
contracts, and the immutable source seed. It first reruns the legacy recipe
on each target using current applied masks and saved head points. A target
uses v4 only if legacy still fails with exactly
`snout_extension_too_long`. If legacy now succeeds, it remains legacy;
other failures also remain legacy. Non-target numerical seed arrays and
edited review arrays, including manual points and deliberate clears, are
carried from their respective sources. The successor snapshots current
applied masks, records any non-target mask differences against the original
seed mask with both digests, and retains the older derivation lineage for
those rows. Crop-border acceptances remain separately bound to their current
mask and row identities.

The new seed and editable pose each store `tail_derivation_method_code`
(`0` legacy, `1` v4) per row. The exact mapping appears in run attributes;
the source proof records target rows, v4 rows, legacy recheck reasons,
source recipe and seed digest, source edit revisions and content digests.
Later ordinary mask Apply validates the immutable method-code hashes and
recomputes each row with its recorded method. It rejects stale or tampered
method identity and arbitrary recipes. Review tasks from this explicit
upgrade scope keypoints to the target rows and mask review to target rows
that still fail; existing review tasks retain their own scopes.

Before any training queue publication, required CI must pass on the exact
code commit. The publisher must run against rechecked current applied
sources under the existing locks. Pending browser checkpoints are outside
the applied snapshot and need coordination before creating a successor.
The output is a training review candidate, not scientific authority or a
production analytics rerun.
