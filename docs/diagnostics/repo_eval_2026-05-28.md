# Repository Evaluation — Palette / fisheye

**Date:** 2026-05-28
**Method:** Read-only parallel sweep — 6 agents, one per dimension (architecture, code quality, testing, docs/contracts, repo hygiene, domain correctness), followed by a synthesis pass. No files were modified.
**Scope at time of eval:** ~400k LOC in `src/`, 1265 Python files, 413 unit-test files, 245+ docs.

---

## The master pattern

The project has the *vocabulary* of correctness everywhere and the *enforcement* in very few places. Contracts, provenance, completion markers, and lineage fingerprints all exist — but the gates default to **silently accepting** rather than **loudly failing**. That gap is where the real scientific risk lives, and it surfaced independently across the architecture, domain-correctness, and docs dimensions.

Two corollaries that recur across dimensions:

- **Effort is inverted relative to scientific risk.** Heaviest testing, tooling, and docs cluster on the registry/backfill/post-processing layers; the irreplaceable core (detection, tracking, video import, background subtraction) is the least tested and least typed.
- **Silent acceptance over loud failure.** `legacy_default=True`, `status='no_spec'`, `best_effort` fingerprints, advisory-only subject-metadata checks, broad provenance normalization. Each is individually defensible; together they form a pipeline that prefers to keep going over telling you something is wrong — the worst default for science.

## Strengths worth protecting

1. **Provenance + completion-marker infrastructure is real and load-bearing.**
   - `src/fisheye/shared/stage_provenance.py` — versioned `STAGE_PROVENANCE_CONTRACT`, `build_stage_provenance()` enforcing required `timestamp`/`parameters`/`inputs`, applied across refinement stages via `mark_run_started`/`mark_run_complete`.
   - `src/fisheye/shared/zarr_run_completion.py` — `RUN_COMPLETION_CONTRACT='palette.zarr_run_completion.v1'` with explicit `running`/`complete`/`failed` statuses written before and after writes.
   - `src/fisheye/shared/run_lineage_fingerprint.py` — deterministic hashing that *excludes* `TRANSIENT_LINEAGE_KEYS` (hostname, timestamp, git_branch, platform) to isolate scientific reproducibility from operational context.
   - `src/fisheye/diagnostics/check_provenance_consistency.py` — reconstructs the detect→crop→keypoint→arena dependency graph; checks bbox drift within 0.25px tolerance and detects stale crop-source snapshots.

2. **Contracts are runtime-enforced in places, not just prose.** 620 references to `schema_version`/`contract` in `src/`; code gates on them (e.g. `bout_classification_runs.py`, `eye_angle_runs`). 35 contracts verified in May 2026 — versioning discipline is current.

3. **Strong typing and test density in the core science.** 513 of 603 files (85%) use `from __future__ import annotations`. High assertion density (`test_registry_maintenance.py`: 142 functions, 1199 assertions). Real-state testing via `tmp_path` with actual zarr stores (4886 occurrences) rather than over-mocking.

4. **Explicit pipeline orchestration.** `STAGE_ORDER` / `STAGE_DEPENDENCIES` in `src/fisheye/core/pipeline.py` (lines 163–195) give a single legible execution spine — the thing that keeps the whole pipeline runnable by one person.

> Protect these by not letting the next refactor casually weaken provenance writes or contract gating to "move faster."

## Weaknesses, ranked by impact on shipping correct science

### Tier 1 — directly threatens correctness of results

All four are instances of the same documented-not-enforced pattern.

1. **`legacy_default=True` silently accepts unmarked/incomplete runs as complete.** `is_run_complete()` (`zarr_run_completion.py` lines 102–114) defaults to `legacy_default=True`, returning `True` for runs lacking the completion contract entirely. 11+ files (`refine_detect.py`, `keypoint_review.py`, `detect_review.py`, `eye_segmentation_yolo.py`, `detect_traditional.py`, `tune/*.py`) call `resolve_latest_complete_run_name(..., legacy_default=True)` with no warning or telemetry. **Highest-risk item in the repo:** a partially-written run can be picked up as canonical and you'd never know.

2. **Array schema validation is enforced for only 1 of 10 stages.** `registry/stage_complete.py` line 64: `_ENFORCE_STAGE_ARRAY_VALIDATION_FOR = frozenset({'detect_quality'})`. The code's own comment admits stages "still need a writer-by-writer audit before every stage can be fail-closed." The other nine stages register in the DB with `status='no_spec'` (a warning, not an error) — missing arrays, wrong dtypes, or inconsistent leading dimensions pass silently. Combined with #1, both main integrity gates are mostly open.

3. **Provenance is diagnosed post-hoc, never enforced at write time.** `diagnostics/check_provenance_capture.py` is a separate CLI that scans archived zarr after runs complete, and only returns non-zero with `--strict`. There is no pre/post-write assertion in the refinement stages. Skip `write_stage_provenance()` or `mark_run_complete()` and the run silently registers with incomplete provenance.

4. **Crop-source drift is detected but never gated.** `check_provenance_consistency.py` (lines 291–346) reports crop-source-drift after the fact. If upstream `refined_detect` is manually curated or re-run, the crop snapshot goes stale — but nothing prevents downstream keypoints from running against it. Diagnostic only; no fail-closed.

### Tier 2 — slows you down and erodes the codebase

5. **`utils/` is a 250-file / 139k-LOC junk drawer.** 248 of 250 files define `main(argv)` — they are scripts, not utilities. 33 near-identical backfill scripts (e.g. `backfill_keypoint_profiles.py` vs `backfill_eye_mask_profiles.py` share identical `@dataclass BackfillRow` / `RegistryDatasetContext` / `_resolve_roots()` boilerplate). 1,900-line `main()` functions (`check_training_registry.py` = 1,899 lines; `registry_query.py` = 1,587). Dominant maintainability tax; surfaces in three dimensions.

6. **Core CV modules have zero direct unit tests.** `detection/detect_yolo.py` (1858 LOC), `capture/import_video.py` (1565), `tracking/crop.py` (3917 — the largest module), `preprocessing/background.py` (291) all untested in isolation. `tests/integration/` exists but is empty. Test distribution skews heavily to backfill/registry/export rather than core CV algorithms.

7. **Stage vocabulary fragmented across 5 disagreeing definition sites.** `pipeline.py` (14 stages), `interactive_launcher.py` (9 stages), `step_cascade.py` (different names: `refined_detect` vs `refine`, `tracks` vs `track`). The `doc_code_divergence_inventory` flags this as "the single most load-bearing fragmentation"; the 2026-05-10 recheck claims only a partial fix (`STAGE_CANONICAL_IDS`).

### Tier 3 — reproducibility / hygiene drag

8. **207MB of tracked binaries + a redundant submodule bloat `.git` to 963MB.** 9 YOLO weights at root (`yolo11m-seg.pt` 44MB, `yolov8s-pose.pt` 23MB, etc.), `decord-0.6.0-...whl` (5.9MB), 136 tracked PNGs (~60MB), plus a 133MB `decord/` git submodule that duplicates the already-tracked wheel. These belong in an external model registry, not git history.

9. **Flag files still tracked despite a commit meant to stop them.** `eye_mask_frame_flags.json`, `keypoint_nudge_flags.json`, `gpu_results.json` remain in git. Commit `9ca9a2a` ("gitignore: stop tracking local retune flags") added `retune_frame_flags*` to `.gitignore` but didn't `git rm` the rest. Root is also polluted with loose `*.json`/`*.txt` session artifacts.

10. **Minimal entry point for a 299-file docs ecosystem.** Root `README.md` is 6 lines (260 chars). No "where to start" guide covering contract philosophy, artifact families, the stage DAG, or how contracts map to code. Contracts reference each other as flat link lists, not a structured dependency map. Only ~5 code→doc links exist in `src/`.

## If you only do three things (subtraction / forcing functions)

1. **Flip the defaults from silent-accept to fail-loud — start with one line.** Change `legacy_default=True → False` (or at minimum emit a warning + telemetry on every legacy acceptance), then expand `_ENFORCE_STAGE_ARRAY_VALIDATION_FOR` one stage at a time until it covers all 10. Highest correctness-per-edit ratio in the repo. Forcing function: make the pipeline refuse to read a run it can't prove is complete.

2. **Make provenance enforcement a write-time assertion, not a CLI you remember to run.** Move the `--strict` check into `mark_run_complete()` so a run physically cannot finalize without valid provenance. Deletes an entire class of "I forgot to validate" and converts your best infrastructure from optional to load-bearing.

3. **Subtract `utils/` and the binaries — declare bankruptcy, don't refactor.** Move the 248 `main(argv)` scripts to `tools/` (delete the dead ones), `git rm` the 207MB of weights + the redundant decord submodule, and stop tracking the flag files. Forcing function: anything left in `utils/` after the move must be import-only (no `main`), which mechanically enforces the helpers/scripts split going forward.

Everything else (README, stage-name unification, integration tests for detect/track) is downstream of these three. Fix enforcement first; the rest is cleanup you can do incrementally without risking the science.
